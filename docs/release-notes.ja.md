# リリースノート — 0.7.0

[トップ](../README.ja.md)

テクニカルデモの更新リリースです。セットアップと起動の手順はこれまでと同じです。案内文、配置先とキャッシュの検査、識別用カートリッジも改善しています。デモ本体には6つ目のシーンとヘッダーの新しい描画方式が加わり、VDP レジスタの1ビットを決め打ちではなくハードウェアへ問い合わせて決めるようになりました。

**Scene 6 AFTERGLOW を追加しました。** ヘッダーを一切出さない画面から始まります。フレーム間で保持するページへ立体を白一色で描き、全画面 LMMV（AND）1回でそのページを毎フレーム1段暗くします。ここでは明るさを色番号の立っているビット数で定義したパレットを使うため、どのビットを落としても元の色によらずちょうど1段暗くなり、残像は均等に黒へ落ちます。さらに保持しているページを毎フレーム少しずつ拡大します。立体は毎回ほぼ同じ画素を覆うため、その場に留まる残像は上書きされて隠れてしまうからです。拡大することで、消えていく複製が立体の下から外へ出ていきます。3秒後にヘッダーが現れ、同じページが再帰フィードバックの履歴になります。前の画面を HMMM で平行移動、または LRMM で拡大・回転し、その上に現フレームの立体を描き、結果を再び取り込みます。CPU によるフレームバッファ処理も実行時の三角関数も使わず、すべて VRAM 間コマンドで構成しています。

**全シーンのヘッダーを、完成した画面へ直接描くようにしました。** 1ドットの黒いドロップシャドウ付きで、透明転送1回です。従来はタイトル文字を背景画像へ焼き込み、ヘッダー部分は背景画像の帯を貼り直していました。Scene 3 でヘッダー部分だけが波打たなかったのはこのためで、貼り直さないと焼き込まれた文字がゴーストとして波打ってしまうからでした。現在この帯も歪みの一部になり、影によって文字はその上でも、他の背景の細かい箇所でも読めます。

**R20 の bit5 を起動時に判定します。** このビットの意味は V9968 の実装ごとに異なります。固定している派生版 openMSX では拡張コマンドの有効化ビットで、落とすと LRMM がまったく動きません。一方 MSXimus から報告された FPGA のマップではフラットインタレースの選択で、そちらは bit5 なしで LRMM が動きます。どちらかに決め打ちせず、ビットを立てずに書いて LRMM を1回実行し、転送先を読み返して、何も起きていなければビットを立てます。実機で検証し差異を報告してくださった MSX Barcelona に感謝します。

Releases の Assets から 0.7.0 の ZIP 全体を新しいフォルダへ展開し、対応する setup BAT を実行してください。既存の 0.5.0・0.6.0・0.6.1 環境はそのまま使えます。上書きセットアップはできず、停止します。

実機での確認は当方では未実施です。検証は固定したエミュレーターのみで、C-BIOS/Z80 と FS-A1GT/R800 の双方で行っています。BIOS・エミュレーター実行ファイルは同梱しません。[デモの制限](../demos/v9968-tech-demo/README.ja.md)と[ベンチマークの測定条件](../demos/scene3-benchmark/README.ja.md)も参照してください。

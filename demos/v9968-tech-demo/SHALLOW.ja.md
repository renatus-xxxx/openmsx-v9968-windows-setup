# Scene 7 — 透明な浅瀬

通常デモで **7** を押すと表示します。**0** で7シーンの自動再生へ戻ります。

角張った細かな石床を、手前ほど太くなる集光模様と、水面に浮かぶ半透明の反射筋で見せます。床と光は同じ固定視点の遠近投影を使います。[Clearwater](https://github.com/Aureliengmz/clearwater) は表現の参考で、コード・素材は独立制作です。

## 光の太さと階調

Pythonで画面の各点を水底へ逆投影します。

```text
d = y + 84
X = 160 * (x - 128) / d
Z = 28800 / d
```

水底座標を複数の進行波で変形し、Voronoiの境界までの距離から光を生成します。画面上の1画素の境界を拾う方式ではないため、奥は細く、手前は幅のある光になります。細い芯と弱い周辺光を2×2小画素で平均してから4段階へ量子化します。幅・強さも波に沿って変化します。

16色は石肌4色×照明4段階に割り当てます。床は色番号0～3、光は0/4/8/12で、LMMM ORが照明段階を選びます。これは半透明や物理的な加算ではありません。床を4色に絞った代わりに光の幅と階調を増やしています。手前の床を明るく、奥を控えめにする近似です。実際の水深やFresnel反射を計算するものではありません。

光は256×160、128形状で、4 tickごとに選択します。60Hzなら最大15形状/秒、周期は約8.53秒です。描画が遅いと中間形状を飛ばします。屈折は別の128位相を使い、1行単位で求めた同じ変位をまとめてHMMM転送します。完成フレームの動画再生ではありません。

## 水面の反射：Sprite mode3

62枚のSprite mode3スプライトを、20枚の白い輝き、低優先度の10枚の淡い光、4枚ずつ接続した8本の半透明の筋に配分します。重ねた光は加算されず、画素ごとに優先する1枚だけが選ばれます。光のにじみの近似であり、加算発光ではありません。独立したパレット1と4段階の透明度で、淡い反射の下に水底を残します。

スプライト同士は優先順位で選ばれ、その後に背景とRGB5で合成されます。複数の反射が加算される方式ではありません。16枚/走査線の上限と、ヘッダー領域を侵さないことを生成時に検査します。現行エミュレーターのスプライト出力は属性Yの1行下になるため、検査もその位置を確認します。

SP3を有効にしてからR5/R6を再設定します。固定しているopenMSXではSP3だけの切り替えでVRAMテーブルの内部マスクが更新されない場合があるため、表示を無効にした状態でテーブルレジスターを一度別値にしてから設定します。シーン退出時はスプライトを無効にし、起動時に選んだR20へ戻します。

## 描画とVRAM

SCREEN 5、256×192、背景16色RGB5、水面領域240×160です。スプライトの別パレットと半透明合成により、最終出力色は背景16色に限定されません。

1. 時刻に合う集光模様をVRAMキャッシュへ更新。
2. ページ3の石床を裏画面へ復元し、屈折の帯をHMMM転送。
3. 集光模様をLMMM ORで合成。
4. 固定ヘッダーを描画。CE完了と垂直同期を待って表示ページを切り替え。
5. パレットとスプライト属性504バイトを更新。

| VRAM範囲 | 用途 |
|---|---|
| 0x00000～0x0FFFF | 表裏画面 |
| 0x10000～0x14FFF | 集光模様20KiB |
| 0x15000～0x15FFF | 筋12種類・淡い光4枠・輝き12種類・空白枠、4 KiB |
| 0x17E00～0x17FFF | スプライト属性領域512バイト |
| 0x18000～0x1DFFF | 石床24KiB |
| 0x1E000～0x1FFFF | 各シーンのヘッダー |

すべて下位128KiB内です。スプライトのパターンは開始時だけ転送し、通常フレームでは属性を更新します。

## ROMと差分転送

8MiB ASCII16-X、割当7,929,856バイトです。8位相ごとの全マスク16個に512KiB、1・2・3位相先への直接差分テーブルにそれぞれ2MiBを使用します。任意の形状は、直前の全マスクと最大3回の差分で正確に再構成でき、128形状をすべて保持します。

9位相以内の更新は最大3回の直接差分を使い、それ以上の飛びは近くの全マスクから復元します。飛ばした中間形状をすべて転送して追いつこうとする処理を避けます。差分の前半・後半はVRAMの16KiB境界で分け、各区間の前にR14を設定します。2・3位相差分は1バンク内に2区間を可変長で収め、先頭のオフセットで後半を参照します。

ASCII16-Xのバンク番号は12bitですが、固定openMSXの実装は8MiBのフラッシュモデルを使用します。16MiBの試作は起動検査に失敗したため採用していません。識別子はバンク511です。Scene 1～6の素材と既存ベンチマークROMは維持します。

## 再生成と検証

生成・画素検査にはPython、Pillow、NumPyが必要です。実行時には不要です。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File build.ps1 -Z88dk "<z88dk root>"
python verify-shallow.py
powershell.exe -NoProfile -ExecutionPolicy Bypass -File test-shallow.ps1 -Runtime "<isolated runtime>"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File test.ps1 -Runtime "<isolated runtime>"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File test.ps1 -Runtime "<isolated runtime>" -CaptureScript measure-shallow.tcl
```

転送処理のOTIRと同等のC言語での実装は、`build.ps1 -CStream -ProfileFilter internal` で切り替えます。続いて `test-shallow.ps1 -CStream` を実行します。

検査は128形状・128屈折位相を個別に網羅し、時間ジャンプとキャッシュの再構成を照合します。スプライトの128位相の属性・常駐パターンも検査します。全組み合わせの総当たりではありません。RGB合成の検査は、不透明・背景・半透明の画像を別々に取り、選んだ位相でRGB5の演算と照合しました。実機・FPGAでの今回の動作は未確認です。

## 共通の波と遠方の減光

コースティックのテクスチャ座標変形を `water_warp()` へまとめ、反射の位置は `follow_water()` でその逆写像に沿って動かします。テクスチャ変位をそのまま足すと、見える模様と逆向きに動くためです。同じ変形場から高さの代理値と傾きを求め、固定視点の鏡面反射を近似します。Pythonで逆写像・照明を事前計算し、MSXでは属性表を転送するだけです。

水底の光には奥行き係数 d（奥0、手前1）から `0.12 + 0.88*d*d*(3-2*d)` の強度を適用します。4段階への量子化前に減光し、奥の光を弱めながら手前の幅と明るさを残します。水底と集光画像は変更していません。表面の反射強度が真下の水底の明るさと一致するわけではありません。

属性は1位相512バイト、128位相で64 KiB。62枚と終端の504バイトを毎フレーム送信します。パターン4 KiB、VRAM内SAT512バイトの配置は維持します。

## 中央に集まる輝き

中央の狭い領域へ20枚の短い斜めの輝きを、不均一な位置で配置します。共通の波に応じて長さ・厚さ・細い消失パターン・0/25/50/75％の透明度を変えます。中央付近を強調する奥行き方向の重みを加え、周辺では薄く消し、等間隔の明るい横棒に見えにくくします。芯はRGB5 (31,31,31)。背後には10枚の斜めにぼけた光を置き、強度が小さいときは非表示にします。

優先度の高いスプライトの非ゼロ画素を選んでから背景と合成します。色0の透明画素では後ろのスプライトが見えますが、半透明画素が後ろのスプライトと混ざるわけではありません。芯と周辺を一緒に設計する必要があります。枚数を増やすだけで最大白を超える明るさやHDRになるものではありません。

Pythonで波の逆写像、有限差分による傾き、固定視点の鏡面反射形状を求めています。共通の高さの代理値を使う物理に着想を得た近似であり、流体シミュレーション・完全なマイクロファセットモデル・水底への集光光線の追跡ではありません。実行時の乱数も使いません。

62枚、全位相で最大11枚/走査線、VRAM128 KiB以内、ROM8 MiB。画素と4段階アルファの量子化は残ります。輝きの密度と淡い光を強めるぶん、水底の一部は見えにくくなります。今回の実機・FPGAでの動作は未確認です。

504バイトの属性転送はOTIRの2ブロック（256＋248バイト）で行います。`-CStream` では同じ出力を行うC言語のループへ切り替えて検査できます。短縮するのは属性転送であり、VDPコマンド自体を高速化するものではありません。

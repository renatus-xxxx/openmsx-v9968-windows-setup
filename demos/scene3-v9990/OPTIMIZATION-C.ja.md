# V9990版C：事前生成パケットとOTIR

## 結果

固定256フレーム列の平均FPS（5秒ウォームアップ、独立起動3回）。B/V9968はハッシュと実行条件が同じ既存結果、Cは今回の最終ROMでの測定です。

| CPU | V9968 | B | 事前生成＋Cループ（診断用） | C：事前生成＋OTIR |
|---|---:|---:|---:|---:|
| Z80 | 15.53 | 5.42 | 7.59 | 14.77 |
| R800 | 15.73 | 10.48 | 12.94 | 20.46 |

Bに対してCは2.72倍／1.95倍。V9968に対して0.95倍／1.30倍です。Cループ診断版は同じパケットを使い、`V9990_C_STREAM_REFERENCE`を定義してOTIR部分をC処理へ切り替えた別ROMです。Z80の385サンプルで独立モデルとの画素一致も確認しました。診断用ROMを通常の版Cと混同しないでください。

採用した変更は、(1)専用パケットによる座標解釈と関数呼び出しの削減、(2)アセンブラでのパケット走査とOTIR送信です。表は段階的な実装比較であり、OTIR命令だけの寄与を独立に測ったものではありません。帯・矩形の結合、端処理の余白化、VRAM姿勢キャッシュは未実装・未測定で、採用した最適化には含めません。

## データと描画

- 元の1 MiB ROMから別の2 MiB ROMを生成します。共有素材とA/B/reference ROMは更新しません。
- Cのbank10〜41：128姿勢、各4096バイト。矩形数16bit＋10バイトの矩形レコード（R36〜43、R48〜49）。境界矩形は4092番地から保持します。
- Cのbank64〜127：256水面位相、各4096バイト。コマンド数16bit＋12バイトの転送レコード（R32〜43）。表示先のページだけ実行時に差し替えます。
- bank54には水面OFF用パケットを置きます。bank127末尾の未使用パディングに識別子を置き、起動時に上位バンクを確認します。
- 矩形は104〜296個／姿勢、水面は端処理込み111〜137コマンド／位相。帯数・矩形数・転送画素数はBと同じです。
- ROMは1 MiB増加。水面テーブル用に1 MiBを予約しますが、パディングを含む容量です。VRAM使用は従来どおり128 KiB、残り384 KiBは未使用です。BSS末尾はBと同じ0xc075です。
- 16色RGB5、背景、半径88の八面体、水面波形、端画素反復、固定ヘッダー、BGM、入力を維持します。

`v9990.c`の各アセンブラストリームに、同じレコードを処理するC実装を`V9990_C_STREAM_REFERENCE`分岐として隣接させています。割り込み処理はレジスターを保存し、送信ポートとROMバンクを変更しません。CEは最大65535回のポーリング後にFAULT=1で停止し、垂直同期停止はFAULT=3です。いずれも割り込みを止めて消音します。

## ビルド・検証

リポジトリのルートから実行します。出力ディレクトリは毎回新しい非公開フォルダを指定してください。

```powershell
python demos/scene3-v9990/build.py --z88dk "<z88dk root>" --variant c
python demos/scene3-v9990/suite.py --kind verify --variants c --runtimes "<runtime parent>" --output "<new private folder>" --timeout 900
python demos/scene3-v9990/suite.py --kind measure --variants c --runtimes "<runtime parent>" --output "<new private folder>" --timeout 900
```

通常起動は`tools/benchmark/launch-scene3-v9990-c-cbios.bat`または`launch-scene3-v9990-c-fsa1gt.bat`です。通常起動にはz88dk/Pythonは不要です。

C参照処理を試す場合は、ビルドで作成した`build/c`一式を非公開の別フォルダへコピーし、同じzccオプションへ`-DV9990_C_STREAM_REFERENCE`を追加してコンパイルします。固定16 KiB領域をパディングし、通常版C ROMの16384バイト以降を連結してください。通常ROM・map・roms.jsonは置き換えないでください。診断結果は[別記録](results-c/c-stream-reference.json)です。

[検証結果](results-c/provenance.json)、[比較数値](results-c/comparison.json)、[異常系・入力検査](results-c/checks.json)、[B/CのVRAM一致](results-c/b-c-pixels.json)を参照してください。

全128姿勢と全256位相を含む385サンプルを両CPUで検査し、BとCの取得VRAM全バイトが一致しました。全128×256組の総当たりではありません。明るい格子背景でも385サンプルを検査しました。固定姿勢37・位相37の撮影画像もRGB画素が一致しています。

パレット負例、外付けVDPなし、CE停止、垂直同期停止、アセンブラストリーム内のCE停止を確認しました。入力・PSGレジスター更新・75秒の連続動作・Escでの消音も確認しています。実機確認、全条件での音の聴感一致は未実施です。

## 時間の内訳と比較上の制限

最終Cの固定列の描画時間はZ80で58.03 ms、R800で37.75 ms。垂直同期待ちは別に約8.64／10.11 msです。表示FPSには要求受渡しの間隔も含みます。

別の32サンプル診断では、ストリーム内CEポーリングが平均約15.60／15.89 msでした。ポーリングにはステータス読取りや割り込みの時間も含みます。残り約42.11／21.88 msは送信、CPU処理、他の待ちなどを含み、純粋な送信時間ではありません。[診断結果](results-c/profile.json)。`profile-c.tcl`は版C専用で、検査する命令バイトを確認したうえでデバッガーを使います。ROMへの計測命令追加はありません。

V9968の機種XMLには継承した`timing=0`があります。その単独効果は未測定です。今回の数値は固定したopenMSX構成・各実装の比較であり、VDP単体や実機の性能比較ではありません。V9968とCの双方がOTIRを使用しますが、コマンド形式・必要設定数は異なります。

## 比較動画

通常再生の別測定値を表示しています。Z80はV9968 15.82／C 15.13 FPS、R800はV9968 15.93／C 20.75 FPSです。固定列の表とは処理する姿勢・位相の列が異なるため、数値も異なります。

上段V9968、下段C。5秒ウォームアップ後の15秒を等速で録画し、Z80→R800の30秒結合版も用意します。白い英語ラベル、H.264/yuv420p/AAC、640×1080。コンテナの60fpsはデモの描画FPSではありません。音声はV9968側のみ、最後2秒をフェードアウトします。録画と性能測定は別に実施しています。動画と生の検証出力はリポジトリ外に保存します。
